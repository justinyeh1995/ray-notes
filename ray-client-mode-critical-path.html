Ray Client 模式關鍵路徑

整理自 2026-10-20 · 分支 fix/ray-init-client-mode · 行號以 master 95d3a43269 加上未 commit 的修改為準 · 延伸自 Issue 67142 Client Mode Reset · ray#67142

一句話:ray.init("ray://...") 會走一條七層的委派鏈,最後把一個 process-wide 的旗標 is_client_mode_enabled 打開,讓所有 @client_mode_hook 修飾的函式改走 Ray Client 路徑。這條鏈上有兩處會打開旗標、三處會關閉旗標,而「打開」和「關閉」的條件並不對稱。

  • 這次修改加在鏈的第 7 層(_ClientContext.connect 的 except),而那一層看不到「別的 context 是否還連著」。
  • 實測結果:修好了 issue 的 repro,但在 allow_multiple 與 _inside_client_test 兩條路徑上造成新的回歸。資料見第 5 節。
  • 建議:改在第 6 層(RayAPIStub.connect)處理,比照既有的 disconnect / shutdown,只在沒有任何 context 存活時才關。

3. 分派決策

每個被 @client_mode_hook 修飾的函式,在被呼叫時都會問一次這個問題。

走 Ray Client 走本機

為什麼這重要:旗標壞掉時,ray.get / ray.put / @ray.remote 全部會改走本機路徑。旗標「卡在 True」時則相反:本機的 ray.init() 起來了,但所有操作都被轉去一個根本沒連上的 client。

4. 旗標的開關點(不對稱)

位置動作條件
client_connect.py:55開無條件(公開 API 路徑)
__init__.py:162開not self._inside_client_test
client_mode_hook.py:78開enable_client_mode() context manager
_ClientContext.disconnect不動只關自己的 worker
__init__.py:374關len(_all_contexts) == 0
__init__.py:404關len(_all_contexts) == 0

__init__.py:222 (本次修改)關無條件 — 唯一一個不檢查其他 context 的關閉點

「開」有兩層條件(其中一層是 _inside_client_test),「關」原本都有「還有沒有別的 context 存活」的把關,這次修改是第一個不遵守這條規則的地方。

5. 實測結果

用 stub 掉 ray._raylet 並替換掉 Worker 的 harness,直接驅動真正的 Python 狀態機(旗標、分派判斷都是真的跑)。修改前後各跑一次同一組情境。

S6 的詳細輸出:A still connected: True 但 A's client-mode dispatch still works? False — A 的連線還活著,可是所有 @client_mode_hook 函式已經不再轉往 client,A 手上那些還在跑的 task 就再也收不到結果。

harness 的限制:驗證的是旗標狀態機與分派判斷(這次修改唯一碰到的地方),不是真的 gRPC 連線。真正的 end-to-end 行為(例如 issue 裡的 AssertionError)仍需要在有 C++ build 的環境跑一次 ray.init() 才算數。

6. 建議的改法

把 __init__.py:222 拿掉,改在 RayAPIStub.connect 處理,條件比照既有的 disconnect / shutdown。

python/ray/util/client/__init__.py · RayAPIStub.connect

def connect(self, *args, **kw_args):
    self.get_context()._inside_client_test = self._inside_client_test
    try:
        conn = self.get_context().connect(*args, **kw_args)
    except Exception:
        global _lock, _all_contexts
        with _lock:
            # 失敗的 context 從來沒被加進 _all_contexts,
            # 所以 len == 0 代表「這次失敗前也沒有任何連線」
            if not self._inside_client_test and len(_all_contexts) == 0:
                _explicitly_disable_client_mode()
        raise
    global _lock, _all_contexts
    with _lock:
        _all_contexts.add(self._cxt.handler)
    return conn

這一層同時滿足三件事:看得到 _all_contexts、看得到 _inside_client_test、而且失敗的 context 根本還沒被登記進去,所以 len == 0 正好就是「可以安全關旗標」的條件。

副作用:_ClientContext.init(__init__.py:299)內部直接呼叫 self.connect,不經過 RayAPIStub.connect,那條路徑不會被這個保護涵蓋。RayAPIStub.init(__init__.py:385)可以加同樣的保護,看要不要一起做。
