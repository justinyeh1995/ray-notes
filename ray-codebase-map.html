Ray Codebase Map

整理自 2026-10-24 · 以 upstream master ce4256ec64 為準 · 相關:Bazel in Ray · Issue 67142 Client Mode Reset

一句話:不用先把 codebase 讀懂。從你呼叫的 public API、traceback 或 log 下手,一次往回追一層。

  • ray.xxx 在哪:打開 python/ray/__init__.py,搜尋那個名字,看它從哪 import。
  • ray xxx CLI 在哪:python/ray/scripts/scripts.py,找 def xxx(。
  • 錯誤在哪:traceback 和 log 都印了檔名和行號,例如 INFO worker.py:1842。
  • 某個函式的行為怪怪的:先看它有沒有掛 @client_mode_hook 之類的 decorator。

1. 怎麼找到程式碼

從 public API 往回追

ray.init、ray.get 這些 ray.* 都是在 python/ray/__init__.py 匯出的:

python/ray/__init__.py:114

from ray._private.worker import (  # noqa: E402,F401
    ...
    init,
    ...
)

所以 ray.init 就是 python/ray/_private/worker.py:1447 的 def init(。

從 CLI 往回追

ray 指令在 python/setup.py:772 註冊:

"console_scripts": [
    "ray=ray.scripts.scripts:main",

所以 ray start 是 python/ray/scripts/scripts.py:801 的 def start(,ray stop 是同檔 1344 行的 def stop(。每個子指令前面都有 @cli.command()。

從 traceback 或 log 往回追

File "python/ray/_private/node.py", line 2272, in _record_stats
    assert ray.experimental.internal_kv._internal_kv_initialized()
AssertionError
2026-10-24 17:18:06,407 INFO worker.py:1842 -- Connecting to existing Ray cluster ...

traceback 由下往上讀,最下面是出錯的那一行,往上是誰呼叫了它。Ray 的 log 格式是 時間 等級 檔名:行號 -- 訊息,行號直接告訴你是哪一行印的。

用 grep 找定義

git grep -n "def _record_stats" -- python
# python/ray/_private/node.py:2270:    def _record_stats(self):

git grep -n "Ray Client is already initialized" -- python
# 從錯誤訊息找到拋錯的地方

git grep 只搜 git 追蹤的檔案,會跳過 bazel-* 那些巨大的 symlink 目錄,比 grep -r 快很多。

2. 三層架構

你的程式 / ray CLI
   │
   ▼
Python API 層       python/ray/             ray.init、@ray.remote、ray.get…
   │
   ▼
Cython 橋接         python/ray/_raylet.pyx   Python ↔ C++,build 出 _raylet.so
   │
   ▼
C++ core           src/ray/                真正執行任務、管理物件

改 Python 層的 .py,editable install 會自動生效。改 _raylet.pyx 或 src/ray/,或是 .proto,要 bazel run //:gen_ray_pkg,見 Bazel in Ray。

3. Python 端:python/ray/

_private/authentication/token auth(RAY_AUTH_MODE)。

actor.py、remote_function.py@ray.remote 的 actor 和 task。

4. C++ 端:src/ray/

位置負責什麼
gcs/GCS(Global Control Service)。整個 cluster 的中央服務,記錄 node、actor、job、placement group,也提供 internal KV。一個 cluster 只有一個,在 head node 上。
raylet/raylet。每個 node 一個,在這個 node 上排程任務、管理 worker process 和資源。
core_worker/CoreWorker。每個 driver 或 worker process 裡的 C++ 核心,負責送任務、追蹤物件參考。_raylet.pyx 包的就是它。
object_manager/在 node 之間傳物件,管理 object store(plasma)。
rpc/、*_rpc_client/gRPC server 和 client 的封裝。
protobuf/所有 .proto 定義,Python 和 C++ 共用。
pubsub/、ray_syncer/node 之間同步狀態。
common/、util/共用工具。
design_docs/設計文件。看不懂某個元件時可以先找這裡。

5. 一個 cluster 裡有哪些 process

ray start --head 之後,ray stop 會說停掉了幾個 process。它們大致是:

  • gcs_server(C++,只在 head node):cluster 的中央服務,預設 port 6379。
  • raylet(C++,每個 node):本機排程。
  • dashboard、dashboard agent、log monitor 等 Python process。dashboard 預設在 8265。
  • Ray Client server:ray start --head 預設開在 10001,ray:// 連的就是它。本機 ray.init() 不會開這個。

你的 driver(跑 ray.init() 的那個 Python process)裡面也有一個 CoreWorker。@ray.remote 的 task 和 actor 跑在 raylet 起的 worker process 裡,每個 worker 也各有一個 CoreWorker。

6. 走過一次:issue 67142

ray.init("ray://...")                 _private/worker.py:1697   "://" 分支
  └─ ClientBuilder.connect            client_builder.py
      └─ client_connect.connect       util/client_connect.py
          └─ _ClientContext.connect   util/client/__init__.py:162  開啟旗標
              └─ 連線失敗,旗標沒被關

ray.init()                            _private/worker.py        本機路徑  ← 修在這裡
  └─ Node(...)                        _private/node.py
      └─ _record_stats                node.py:2270
          └─ _internal_kv_initialized()   experimental/internal_kv.py:28  @client_mode_hook
              └─ 被轉到沒連上的 client → False → AssertionError

追的順序:traceback 指到 _record_stats → 看它 assert 的函式 → 發現掛了 @client_mode_hook → 去看 hook 用什麼條件決定轉不轉 → 找到全域旗標 → 找誰開、誰關這個旗標。

深層的 assert 通常只是症狀。先問「它檢查的東西為什麼是錯的」,一路往回追到狀態第一次出錯的地方,再決定是修源頭,還是在最早能察覺的入口擋下來。只修 assert 那一行,錯誤通常會換個地方再冒出來。

7. 容易踩的坑

  • decorator 會改變行為。@client_mode_hook 會在 client mode 時把呼叫轉到 Ray Client,所以函式本體寫的不一定是實際執行的。@PublicAPI、@DeveloperAPI 只是標記 API 的穩定程度。
  • 同名的檔案很多。_private/worker.py(driver/worker)和 util/client/worker.py(Ray Client 的 client 端)完全是兩回事。看 traceback 時要看完整路徑。
  • module 層級的全域變數。像 client_mode_hook.is_client_mode_enabled 這種用 global 改的變數,要透過 module 讀,from ... import 拿到的是快照,見 Issue 67142 第 7 節。
  • Python 和 build 不同步。原始碼是新的,不代表 _raylet.so 和 core/generated/ 也是新的。拉了新 commit 之後出現奇怪的 AttributeError,先懷疑 build。
  • server 和 client 可能在同一個 process。Ray Client 的測試和 helper 會在同一個 process 裡同時跑 server 和 client,靠 disable_client_hook() 區分。在 ray.init 加檢查時要考慮這種情況。
